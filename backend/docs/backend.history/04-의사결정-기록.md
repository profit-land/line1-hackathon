# 04. 의사결정 기록

## ADR-01. 기존 Spring Boot 스택 유지

- 결정: Java 21, Spring Boot, JPA 구조를 유지한다.
- 이유: `feat/backend-setup`의 코드와 팀 작업을 이어가며 변경 비용을 줄인다.

## ADR-02. Access Token + 회전형 Refresh Token

- 결정: Access Token은 JWT, Refresh Token은 임의 문자열로 발급하고 해시만 DB에 저장한다.
- 이유: Refresh Token 폐기와 재사용 감지가 JWT 단독 방식보다 명확하다.

## ADR-03. 이미지 업로드 두 방식 지원

- 결정: 기존 multipart 방식과 2단계 업로드 계약을 모두 유지한다.
- 이유: 기존 프론트 호환성을 지키면서 향후 외부 Object Storage로 이동할 수 있다.

## ADR-04. 분석 작업은 비동기 처리

- 결정: DB에 작업을 먼저 저장한 뒤 `AFTER_COMMIT` 이벤트와 전용 executor로 처리한다.
- 이유: 요청을 빠르게 반환하고 중간 진행률을 조회할 수 있다.

## ADR-05. 분석 결과를 현재 PageExpression으로 재사용

- 결정: 별도 Vocabulary 마스터를 즉시 추가하지 않고 기존 분석 표현을 학습 기능의 원본으로 사용한다.
- 이유: 중복 테이블과 마이그레이션 위험을 줄이고 현재 구현을 바로 연결한다.
- 후속: 공용 콘텐츠 검수 기능이 필요해지면 Vocabulary 마스터로 분리한다.

## ADR-06. 외부 AI 공급자는 경계 뒤에 배치

- 결정: 공급자가 없는 동안 결정적 로컬 구현을 사용한다.
- 이유: 프론트 연동과 DB 흐름을 먼저 검증하면서 공급자 선택을 늦출 수 있다.

## ADR-07. 소유권 실패는 404

- 결정: 다른 사용자의 리소스 접근은 403 대신 404로 처리한다.
- 이유: ID 존재 여부 노출을 방지한다.
