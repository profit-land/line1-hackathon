# 02. 구조와 핵심 개념

## 1. 패키지 구조

```text
com.line1.booktalk
├─ domain
│  ├─ auth          인증과 Refresh Token
│  ├─ user          보호자 계정
│  ├─ child         아이 프로필
│  ├─ book          도서와 촬영 페이지
│  ├─ upload        2단계 업로드
│  ├─ analysis      비동기 페이지 분석과 표현
│  ├─ learning      북마크·학습·문장·복습
│  ├─ conversation  AI 대화
│  ├─ notification  알림 설정과 기기
│  └─ speech        TTS·STT 계약
└─ global
   ├─ auth          JWT 인터셉터와 @LoginUser
   ├─ common        ID, cursor, hash, 언어
   ├─ config        Web, CORS, JPA, Async
   ├─ error         공통 오류 처리
   ├─ filter        X-Request-Id
   ├─ response      응답 envelope
   └─ storage       비공개 파일 저장소
```

## 2. 요청 처리 흐름

1. `RequestIdFilter`가 요청 ID를 생성하거나 검증한다.
2. `AuthInterceptor`가 공개 경로를 제외한 요청의 Bearer Token을 검증한다.
3. `@LoginUser`가 토큰의 사용자 ID를 컨트롤러 인자로 전달한다.
4. 서비스 계층이 소유권과 상태를 검증한다.
5. JPA 엔티티가 상태 전이를 수행한다.
6. 성공 응답은 `ApiResponse`, 실패 응답은 `ErrorResponse`로 통일한다.

## 3. 핵심 원칙

- 다른 사용자의 리소스는 존재 여부를 노출하지 않고 `404`로 응답한다.
- 기기 ID, Refresh Token, Push Token은 원문 대신 SHA-256 해시를 저장한다.
- 이미지 원본은 공개 URL로 노출하지 않는다.
- 학습 이벤트와 대화 메시지는 클라이언트 ID를 이용해 중복을 방지한다.
- 페이지 분석은 요청 트랜잭션 커밋 후 별도 스레드에서 처리한다.
- 외부 AI는 인터페이스 또는 서비스 경계 뒤에 둔다.

## 4. 상태 머신

### 분석 작업

```text
QUEUED → RUNNING → COMPLETED
             ├──→ FAILED
             └──→ REJECTED
QUEUED/RUNNING → CANCELLED
```

### 학습 진행

```text
NEW → VIEWED → SENTENCE_DONE → CONVERSATION_DONE
```

### 대화 세션

```text
ACTIVE → COMPLETED
```
