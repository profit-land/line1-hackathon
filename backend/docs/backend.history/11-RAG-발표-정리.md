# 11. RAG 발표 정리

이 문서는 현재 구현된 RAG 기능을 발표에서 과장 없이 설명하기 위한 순서와 표현을 정리한다.

## 1. 문제 정의

일반 생성형 AI가 그림책 표현과 부모 코칭 내용을 바로 생성하면 다음 문제가 생길 수 있다.

1. 그림책이나 학습 기록에 없는 내용을 생성할 수 있다.
2. 아이의 연령과 설명 언어가 반영되지 않을 수 있다.
3. 답변의 출처를 확인하기 어렵다.
4. 틀린 표현 관계가 반복적으로 사용될 수 있다.

따라서 이 프로젝트는 자연스러운 문장 생성보다 **검증된 근거와 정확성**을 우선한다.

## 2. 해결 방향

발표 문구:

> 검증된 학습 데이터를 기반으로 Hybrid RAG, GraphRAG, 제한형 PlanRAG 파이프라인을 구현했습니다.
> 질문 유형에 따라 검색 방식을 선택하고, 근거 ID와 신뢰도를 제공하며, 근거가 부족하면 답변을
> 추측하지 않고 보류하도록 설계했습니다.

## 3. 전체 처리 순서

```text
사용자 질문
  ↓
질문 유형·복잡도 분류
  ├─ 단순 정의·예문 → Hybrid RAG
  ├─ 유사 표현·관계 → GraphRAG Local
  ├─ 전체 주제·경향 → GraphRAG Global
  └─ 연령·이력·표현을 함께 고려 → PlanRAG
  ↓
근거 묶음 생성
  ↓
근거 기반 답변 구성
  ↓
인용·근거 커버리지 검증
  ├─ 통과 → 답변·출처·신뢰도 반환
  └─ 실패 → 답변 보류
```

## 4. Hybrid RAG

단순한 표현 정의나 예문 질문에 사용한다.

현재 구현:

1. BM25 기반 키워드 검색
2. 외부 모델이 필요 없는 deterministic semantic feature hashing
3. 제목 및 정확한 표현 일치 가중치
4. 검수 콘텐츠 우선 가중치
5. 점수순 evidence 정렬

예시 질문:

```text
두근두근은 무슨 뜻이야?
```

## 5. GraphRAG

표현 사이의 관계와 사용 상황을 탐색한다.

### Local Search

관련 표현 node를 찾은 뒤 최대 depth 2까지 주변 관계를 탐색한다.

```text
두근두근
  ├─ HAS_TYPE → 의태어
  ├─ FROM_PAGE → 그림책 페이지
  ├─ LEARNING_TARGET → 아이 프로필
  └─ SAME_TYPE → 유사 유형 표현
```

### Global Search

그래프의 연결된 지식 군집을 구성하고 전체 주제·경향·공통점을 조회한다.

예시 질문:

```text
우리 아이가 학습한 표현들의 공통 주제를 알려줘.
```

### 정확성 보호

그래프 관계는 LLM이 임의로 만들어 저장하지 않는다. Spring 백엔드가 소유권과 DB 데이터를 검증한 뒤
`아이–표현–유형–페이지` 관계를 생성한다.

## 6. PlanRAG

한 종류의 데이터만으로 답하기 어려운 질문에 사용한다.

예시 질문:

```text
4세 아이의 학습 이력을 보고 두근두근을 어떻게 가르칠지 추천해줘.
```

실행 가능한 도구:

1. `PROFILE_LOOKUP` — 아이 연령과 설명 언어
2. `HISTORY_LOOKUP` — 문장 연습과 학습 이벤트
3. `HYBRID_SEARCH` — 표현 정의·예문 검색
4. `GRAPH_LOCAL` — 주변 표현 관계 탐색
5. `GRAPH_GLOBAL` — 전체 지식 군집 탐색

플래너는 허용된 도구만 사용할 수 있으며 기본 최대 4단계로 제한한다. 무제한 자율 Agent loop는 사용하지 않는다.

## 7. 토큰 없이 답변한다는 의미

현재도 답변은 반환된다. 다만 외부 LLM이 새로운 문장을 생성하는 방식이 아니라, 검색된 근거 문장을
안전하게 선택하고 evidence ID를 붙이는 추출형 방식이다.

```text
확인된 근거를 바탕으로 답변드릴게요.

- 두근두근은 기대되거나 긴장될 때 가슴이 뛰는 모양을
  나타내는 말이에요. [exp_123]
```

현재 상태:

| 항목 | 상태 |
|---|---|
| 외부 LLM API 키 | 불필요 |
| LLM 입력·출력 토큰 비용 | 없음 |
| RAG 검색·계획·그래프 탐색 | 구현됨 |
| 근거 기반 추출형 답변 | 구현됨 |
| GPT 등 자연어 생성 모델 | 미연결, 교체 가능한 구조 |

## 8. 답변 검증

답변을 사용자에게 반환하기 전에 다음을 검사한다.

1. 답변에 사용된 evidence ID가 실제 검색 결과에 존재하는가
2. 답변의 핵심 단어가 evidence에 포함되는가
3. 답변 전체의 evidence coverage가 기준 이상인가
4. retrieval confidence가 최소 기준 이상인가
5. 검증되지 않은 주장이 포함되었는가

검증에 실패하면 다음과 같이 응답한다.

```text
검색된 근거끼리 일치하지 않아 답변을 보류했습니다.
보호자 또는 콘텐츠 검수자의 확인이 필요합니다.
```

## 9. 발표에서 말해도 되는 구현 범위

- Hybrid RAG 구현
- 질문 유형별 RAG 자동 라우팅
- GraphRAG Local/Global 탐색
- 최대 단계가 제한된 PlanRAG
- 아이 프로필·학습 이력·표현 관계 검색
- evidence ID 및 citation 반환
- confidence 계산
- 답변 근거 검증
- 근거 부족 시 abstention
- Spring 백엔드와 Python AI 서비스 분리
- 실제 LLM을 교체 연결할 수 있는 `AnswerGenerator` 인터페이스

## 10. 피해야 할 표현

현재 상태에서 다음 표현은 사용하지 않는다.

- “GPT를 연동했습니다.”
- “상용 LLM이 답변을 생성합니다.”
- “Microsoft GraphRAG 패키지 전체를 적용했습니다.”
- “외부 임베딩 모델과 Vector DB를 사용했습니다.”
- “완전 자율 AI Agent입니다.”

대신 다음과 같이 표현한다.

> RAG 검색·계획·그래프 탐색과 정확성 검증을 구현했고, 현재 답변 생성은 추출형 안전 생성기를
> 사용합니다. 실제 LLM은 동일한 근거·인용·검증 계약을 유지한 채 교체 연결할 수 있습니다.

## 11. 시연 순서

### 시연 1 — 단순 질문

```text
질문: 두근두근은 무슨 뜻이야?
예상 route: HYBRID
확인 항목: 답변, exp evidence ID, confidence
```

### 시연 2 — 관계 질문

```text
질문: 두근두근과 비슷한 표현은 어떤 관계야?
예상 route: GRAPH_LOCAL
확인 항목: 표현·유형·페이지 관계
```

### 시연 3 — 개인화 복합 질문

```text
질문: 4세 아이의 학습 이력을 보고 두근두근을 어떻게 가르칠지 추천해줘.
예상 route: PLAN
확인 항목: PROFILE_LOOKUP → HISTORY_LOOKUP → HYBRID_SEARCH → GRAPH_LOCAL
```

### 시연 4 — 근거 부족

```text
질문: 저장되지 않은 표현에 대해 알려줘.
예상 결과: abstained=true
확인 항목: 근거 부족 사유와 답변 보류
```

## 12. 예상 질문과 답변

### Q. 실제 LLM을 사용했나요?

현재는 사용하지 않는다. 정확성과 비용을 먼저 검증하기 위해 추출형 생성기를 사용하고 있으며,
실제 모델은 `AnswerGenerator` 구현으로 연결할 수 있다.

### Q. 이것도 RAG라고 할 수 있나요?

그렇다. 외부 지식 검색, 검색 결과 증강, 근거 기반 답변 구성과 검증이 구현되어 있다. 생성 단계가
LLM일 필요는 없으며 현재는 환각을 줄이기 위해 추출형 생성기를 선택했다.

### Q. GraphRAG 관계도 AI가 만들었나요?

아니다. 현재 관계는 검증된 DB 데이터에서 생성한다. 잘못된 AI 관계가 장기 저장되는 위험을 줄이기 위한 결정이다.

### Q. 실제 LLM을 붙이면 무엇이 달라지나요?

검색·계획·그래프·검증은 유지되고, 근거 문장을 더 자연스럽고 개인화된 문장으로 만드는 생성 단계만 변경된다.

### Q. 정확성은 어떻게 평가하나요?

retrieval 적합도, citation validity, evidence coverage, abstention 정확도를 분리해 평가한다. 이후 검수된 질문·정답
세트를 만들어 route별 회귀 테스트를 수행한다.

## 13. 한 문장 요약

> 검증된 데이터만 검색하고, 질문에 따라 Hybrid·Graph·Plan RAG를 선택하며, 근거가 없으면 답하지 않는
> 정확성 우선 AI 답변 파이프라인을 구현했습니다.
